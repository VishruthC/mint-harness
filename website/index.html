01 / QUICKSTART

One command. Then it’s yours.

Install MINT globally, run it inside any project, and connect your NVIDIA key. No clone, no build step, no config file required.

  1. 01
    Install the CLI

    npm install -g mint-harness — Node and npm handle the install.

  2. 02
    Open your project

    cd path/to/your-project then start minth.

  3. 03
    Connect NVIDIA NIM

    Run /connect once, or add NVIDIA_API_KEY to a local .env.

02 / HOW IT WORKS

One turn. You stay in control.

Every request follows the same bounded loop. Tools can read or propose; only you can approve.

  1. 01
    You ask.

    A message enters the harness.

  2. 02
    Registry builds the prompt.

    Only registered capabilities are described.

  3. 03
    NVIDIA NIM streams.

    OpenAI-compatible tool calls, one turn at a time.

  4. 04
    Tools read or propose.

    Reads return data. Writes and commands stop at the gate.

  5. 05
    You approve.

    /apply for patches. /run for commands. The model cannot self-approve.

  6. 06
    The result returns.

    Tool output goes back to the model.

  7. 07
    The answer lands.

    Bounded by 12 rounds and 24 calls per turn.

03 / WORKSPACE

Context with guardrails.

Bounded reads, explicit proposals, and sensitive files refused by name.

MINT launches inside a workspace. It can list, read, search, and discover project context — but it cannot wander outside the root, follow a symlink into the rest of your machine, or open the files you keep private.

01

Only inside the workspace.

Paths are resolved and symlink targets are canonicalized. Outside means outside.

02

Sensitive files stay shut.

.env, .env.*, id_rsa, id_ed25519, *.pem, and *.key are refused by name.

03

Generated noise is skipped.

.gitignore is respected alongside built-in exclusions for node_modules, dist, coverage, and friends.

04

Bounded by default.

Reads cap at 256 KB. Search caps at 1 MB per file, 1,500 files, and 100 matches.

“The model can inspect. It cannot wander.”

04 / APPROVAL

The model proposes. You decide.

Every patch and every command stops here. Approval is explicit, single-use, and never self-granted.

✓

✓

The file hash is revalidated before applying.

05 / LOCAL DATA

Memory that stays home.

Sessions are created lazily on the first message. Each one remembers its own model.

Conversation history lives in SQLite at ~/.mint/mint.sqlite, or under MINT_DATA_DIR. Resume a session, rename it, delete it. The database stays on your machine.

01

Per-session model selection, restored on resume.

02

Restrictive directory and file permissions where supported.

03

06 / FULL STACK

Every layer. One binary.

Interface, runtime, model gateway, and local data ship together. No hosted backend required to start.

A terminal that feels designed.

SolidJS and OpenTUI render streaming chat, session state, approval cards, and one very opinionated cat — all inside the terminal.

  • OpenTUI
  • Streaming UI
02 RUNTIME

A bounded agent loop.

A Bun-native runtime builds the tool registry, streams model responses, and enforces hard limits on rounds and tool calls.

  • TypeScript
  • 12 rounds / 24 calls

NVIDIA NIM at the core.

08 / TRUST

Trust is a feature.

No browsing. No external apps. No sandbox claims. A short, honest ledger.

Works today

  • NVIDIA NIM streaming
  • SQLite sessions and resume
  • Workspace list, read, and search
  • Project context discovery
  • Patch and full-file proposals
  • Approval-gated terminal commands
  • Persistent pixel cat

Not yet

  • Web browsing
  • External app control
  • OS credential-store integration
  • Multi-step task planning
  • Searchable session history
  • Session export and import
  • Context compaction

Not a sandbox

Approved commands can still perform consequential operations. The allowlist, blocked-argument checks, timeout, and output cap are a safety layer — not a sandbox. Inspect every preview.

MINT never claims a file was read, a command ran, or a site was browsed unless a tool result confirms it.
